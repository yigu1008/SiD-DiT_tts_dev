# VLM readout + Jev decisions inside key-step MCTS on base SD3.5-Large (started 2026-10-16)

## Question
Does a decision model that *sees* the trajectory (x0 preview + a VLM readout) and picks the next (prompt wording, CFG)
action beat blind search at matched budget, on a sampler where the per-step MDP is real (28 Euler steps, 8 branch points)?
This is the base-SD3.5 counterpart of the SiD search-vs-fixed ablation, where 4 steps made MCTS depth-1 in practice.

## Pipeline per tree node (jev_prune arm)
1. x0 preview = decode(node.dx) at the node's key step (root: no image).  Saved at 512 px -> `previews/`.
2. Perception: Qwen2.5-VL-7B-Instruct, prompt = ORIGINAL prompt + preview, asked for a <=2-sentence readout
   (matches / missing / at risk), explicitly *no* setting suggestions.  (`vlm_server.py /generate`)
3. Decision: Jev-Omni (akhilaaa3/Jev-Omni rev 5addda86, pinned snapshot, order-averaged over 3 shuffled option orders,
   same scheme as jev-cub/src/omni.py).  State = ORIGINAL prompt + step + readout; image attached when depth > 0.
   Q1 choice over the 4 prompt wordings (variants); Q2 choice over the 7 CFG levels.  (`jev_server.py /ask`)
4. Node candidate set = top-2 wordings x top-3 CFGs by Jev probability (+ baseline anchor (variant 0, CFG 4.5)).
   Rollouts from a leaf sample uniformly from the leaf's kept set at all remaining key steps.
5. Everything else is the stock search: UCB1 c=1.41, untried-first, ImageReward terminal reward against the ORIGINAL
   prompt, return best rollout vs exploit replay.  Decisions + probabilities + spreads logged to `decisions.jsonl`.

## Held-out evaluation (judge_base.sh)
HPSv3, PickScore, HPSv2, VQAScore (CLIP-FlanT5), and the Qwen2-VL-7B alignment judge.  Caveats: ImageReward is the
optimized objective (report, not evidence); the alignment judge is a different checkpoint from the Qwen2.5-VL reader
but the same family, so HPSv3 / PickScore / VQAScore are the clean held-out metrics.  Paired per prompt, 10,000
prompt-bootstrap resamples, 95% intervals; zero-crossing = inconclusive.

## Known risks / limits
- VLM readouts sometimes treat variant content (e.g. "sunset") as part of the prompt; the readout prompt now shows ONLY the
  original prompt, and Jev sees the wordings only as options.
- Jev CFG decisions had large order-spread on the test image (max 0.39); the wording decision was sharp (0.99).
- Budget: one 28-step CFG rollout ~21 s, so 40 sims ~15 min/prompt per arm (probe numbers below).  Budget-matching across
  arms is by simulations (identical transformer NFE); VLM/Jev time is extra wall-clock, reported separately.
- Servers: IR (reward env, GPU 1, :5141), Qwen2.5-VL (sid_dit env, GPU 3, :5151), Jev-Omni (jev env, GPU 6, :5161);
  `keepalive.sh` restarts a dead server; arms retry reward/VLM/Jev calls for up to 15 min.  The IR server died once
  (19:51, no log, external) and killed the first probe.

## Probe (prompt q0000, 40 sims) -- see PROBE.md (regenerated by scripts/make_probe_md.py)
Findings that change the design:
- The stock `run_mcts` default for steps>4 appends a sparse-noise refine pass (`--mcts_sparse_noise_refine`), ~+1000 NFE
  (3208 vs ~2200). `mcts` now disables it (basic search, comparable to the pruned arms); `mcts_refine` keeps the default.
- MCTS reuses stored prefixes, so NFE depends on tree shape: the flat 28-action stock tree spends ~2200 NFE per 40 sims,
  the deeper pruned trees ~2000. Equal sims is therefore slightly *unfavourable* to the pruned arms in NFE; report NFE
  with every arm (records carry `nfe_transformer` and the independent `segment_steps`).
- Cost per prompt (one RTX 6000 Ada): baseline 49 s; stock basic ~18 min; refine ~21 min; rand_prune 14 min;
  vlm_prune 17 min (41 VLM calls, 229 s); jev_prune 18 min (41 readouts + 82 Jev questions, 246 s). Peak 25.7 GiB.
- n=1 picture: stock+refine maximised ImageReward (+0.25) but lost HPSv3 −3.8 / PickScore −0.9 (over-saturated,
  malformed wording v3 at CFG 7.0); basic stock (refine off) IR +0.17 with HPSv3 +0.36; VLM/Jev-decided arms IR +0.16/+0.11
  with HPSv3 +0.5/+0.7 at ~10% fewer NFE; random pruning IR +0.14 but HPSv3 −1.0. Illustrative only.
- Jev: picks the original wording at 40/41 nodes (p≈0.94); CFG choice weak (top-prob 0.31, order-spread 0.35).

## Arm 6 (added 2026-10-16 22:20): `opt_prompt` — deliberate discrete prompt optimizer (offline, per prompt)
`scripts/opt_prompt_arm.py`. No reward is consulted inside the loop; only faithfulness and completeness.
1. Checklist: VLM (text only) decomposes the ORIGINAL prompt into typed atomic elements (object, count, attribute, spatial/action relation,
   comparison, negation, style, scene, text).  Saved to `checklists/<pid>.json`.
2. Round r: encode current wording -> plain 28-step sample at CFG 4.5, seed 42 -> VLM grades every element present / wrong / missing.
3. Propose: VLM (text only) writes K=4 candidate wordings, each ONE typed operator on the current wording aimed at a missing/wrong
   element: emphasize | reorder | clarify | drop_clause | revert.  Hard rule: nothing added beyond the original, nothing dropped.
4. Guard: Jev-Omni yes/no (text, 2 orders) "same scene, nothing added, nothing removed?"  P(yes) < 0.5 -> discarded.
5. Decide: Jev-Omni choice over surviving candidates + "keep current wording" (state = original + checklist statuses + current wording,
   media = latest image).  Stop on keep / all present / no candidate passes / 4 rounds.
Output = the round with the most `present` elements (ties -> latest).  Everything (images per round, statuses, candidates with guard P(yes),
Jev probabilities) is in records.jsonl and `rounds/`; `scripts/make_optprompt_sheet.py` renders one eye-check sheet per prompt.
Role in the ablation: the "deliberately optimized static wording" control (replaces the cached-rewrite bank as the fixed-prompt baseline)
and the candidate anchor wording for the online variant (edits at key steps 0 and 4 only) if the checklist readout proves accurate.
First test: `scripts/run_optprompt_probe.sh 5` (waits for two ryan-free GPUs; IR+sampler on one, VLM+Jev on the other) on the first
5 cohort prompts (mountain range; kitten-left/butterfly-right; four dresses; umbrellas of varying colors; two birds long/short tail),
then check the checklist accuracy by eye on the sheets before trusting the loop.

## opt_prompt iterations (2026-10-17 00:45–01:45, OPTPROMPT.md has the tables and sheets)
- v1 (lenient readout): 5/5 prompts graded all-present at round 0, two of them wrongly (dresses hemline contrast, birds tail contrast) -> no edits ever triggered.
- v2 (observe-then-grade + per-element Jev verification with image): catches both; birds improved 2/6 -> 5/6 via “the higher-flying bird having a long tail” (image gained a long tail streamer);
  dresses stuck because the strict guard rejected the one edit stating the implied contrast; Jev oscillated between original and improved wording (revert allowed).
- v3 (guard allows logically implied contrasts, threshold 0.7, no-repeat, 896 px previews): 3/5 hard prompts improved — birds 1/6 -> 6/6, train toys 0/4 -> 4/4
  (“separated by gaps to ensure they are not adjacent”; trains visibly apart), bracelets 0/4 -> 3/4 (“wearing three silver bracelets”). Dresses and gemstones unchanged:
  the proposer leaked observed attributes (“the multicolored dress”) into edits, so the useful contrast edit was (correctly) rejected as added content.
- v4 (queued): proposer sees statuses only (no notes), must use the original's vocabulary + a small emphasis word list, with a lexical retention / no-new-content filter before the Jev guard.
Known noise: Jev per-element verification disputes trivially true statements (“exactly two birds”, “on the floor”) ~1 element per round; consistent across rounds so the output rule is unaffected.
- v4 (strict no-new-content lexical filter): too restrictive — blocked useful clarifying verbs (“ensure”, “lie”); trains fell back to 1/4, birds 5/6, bracelets 4/4 but HPSv3 −1.0.
- v5 (lexical filter = retention only, Jev guards additions, sampled retries): best configuration. Changed wording on 4/5 hard prompts; held-out deltas vs the
  original wording (same seed): birds VQAScore +0.16 / PickScore +0.61 / IR +0.34; trains HPSv3 +0.76 / VQAScore +0.12 / IR +0.57; bracelets HPSv3 +4.25 /
  PickScore +0.92; dresses unchanged (wording cannot move the hemline prior at this seed); gemstones unchanged. n=4, illustrative.
- Decision: `opt_prompt` = v5 configuration (current scripts/opt_prompt_arm.py). Cost ≈ 5–6 min/prompt when edits run (4 rounds), ≈ 1 min when round 0 passes.
- Next: (a) run opt_prompt on the 25-prompt cohort as the “deliberately optimized static wording” control and judge it with judge_base.sh;
  (b) online variant: wording edits at key steps 0 and 4 + CFG actions, Jev decides — only after (a) shows the readout is reliable at scale.

## Arm 7 (added 2026-10-17 21:55): `jev_online` — online wording generation inside the search
`scripts/jev_online.py`, launched by `scripts/run_online.sh <ids> <prefix> [sims] [max_wait_min]`.
Identical to `jev_prune` in every respect (same 4 cached starting wordings, same CFG bank, same key steps, UCB1 c=1.41,
40 sims, same keep geometry top-2 wordings x top-3 CFGs + anchor, same ImageReward terminal reward) EXCEPT: at nodes of
depth <= `--online_depth` (default 1, i.e. steps 0 and 4) the node additionally
  1. grades the original prompt's checklist on its own x0 preview (observe-then-grade VLM + per-element Jev verification),
  2. asks for K=3 typed edits of THAT node's current wording aimed at its missing/wrong elements,
  3. filters them with the lexical retention check and the Jev faithfulness guard (>= 0.7),
  4. ENCODES the survivors mid-trajectory and appends them to this prompt's embedding bank (cap 12 wordings),
so later nodes can also select them. Deeper nodes never add wordings; composition is committed by step 8.
The contrast `jev_online - jev_prune` therefore isolates exactly one thing: generating preview-conditioned wordings
during the search versus choosing among four wordings written before sampling started.
Why depth <= 1: the step-4 preview already shows composition (eye-checked), and mid-trajectory encoding needs the T5
encoder on the GPU, which forces a transformer park/unpark swap per event (~6 s), so events must stay few.
First test: 3 prompts where we know wording matters (q0011 dresses, q0027 birds, q0041 train toys), both arms, then
judge_base.sh + paired contrasts into `main/contrast_probe3_online_minus_prune.txt`.
Caveat carried forward: the checklist grader is still unvalidated against VQAScore (see the n=25 cohort reading in
OPTPROMPT.md), so a gain here needs the same scepticism — the clean metrics are HPSv3, PickScore, HPSv2, VQAScore.

### jev_online first result (2026-10-17 23:35, n = 3 dev prompts, budget-matched at 2032 NFE)
`main/contrast_probe3_online_minus_prune.txt`. Online wording generation minus the fixed 4-wording bank:
ir −0.137 [−0.202, −0.010], hpsv3 −0.773 [−2.146, −0.040], pickscore +0.015 n.s., hpsv2 −0.008 n.s.,
vqascore −0.026 n.s., qwen_alignment −0.180 n.s. **No metric favours the online arm; the two whose intervals
exclude zero are both against it.** A bootstrap over 3 points is barely interpretable, so treat the intervals as
decoration and the direction as the finding: generating wordings during the search did not help and plausibly hurt.
Mechanism hypothesis: the keep geometry is unchanged (top-2 wordings), so a 12-wording bank gives Jev a noisier
12-way ranking to pick 2 from, instead of a 4-way one; the extra wordings dilute rather than enrich. The bank hit its
cap of 12 on every prompt after only 2-3 nodes, so most depth-1 nodes generated nothing anyway.
Cost: same wall-clock as the control (~17 min/prompt); the online machinery adds ~21% (VLM ~100 s, Jev ~45 s,
mid-trajectory encoding ~70-115 s over 7-8 park/unpark swap events).
Sweep queued to test the mechanism: wide (keep 3 wordings x 3 CFGs, cap 24), deep (generate also at step 8),
k5 (5 edits/node), root (root-only generation, no preview conditioning -- the ablation that isolates whether
preview conditioning matters at all). Dev set = these same 3 prompts; a disjoint 6-prompt test set
(`config/prompt_ids_test6.txt`) is reserved so the winning config is not evaluated on its selection set.

## Decision state for Jev (added 2026-10-18 02:30): `scripts/state_store.py`
Two layers, both rendered as text blocks injected into Jev's `state` and the proposer's instruction, behind `--use_state`:
1. **PromptState** (within one prompt): for every wording in the bank, how often trajectories using it were tried and
   their mean/best terminal reward — the same evidence UCB1 already has, surfaced to the decision model; plus the action
   path to the current node; plus the realised checklist delta of each edit made so far ("`emphasize` fixed element 2,
   broke none, 1 -> 2 present"). This directly attacks the failure the sweep exposed: Jev was re-ranking a growing bank
   from scratch at every node with no memory of what had been tried or how it turned out.
2. **WordingBase** (across prompts, append-only JSONL at `state/wording_base.jsonl`): for each (checklist element type,
   operator) pair, how often that edit actually flipped that element to `present` in the child's readout. Rendered as a
   prior ("count: the `emphasize` operator fixed it 7/9 times") into the proposer and Jev's state.
   `WordingBase(path, frozen=True)` reads but refuses writes — **the base must be built on a training split and frozen
   before evaluating on the held-out split, or the test numbers are contaminated.**
Note this changes what the decision model is: with PromptState it sees reward-derived value estimates, so the Jev arms'
decisions are no longer reward-free (they already were not, since the terminal objective is ImageReward; but the
`opt_prompt` arm, which is reward-free by construction, must NOT be given PromptState if that property is to be kept).
A/B queued: `sw_best` (wide gate + 5 edits, no state) vs `sw_beststate` (same + state) on the dev prompts, so the state
contribution is isolated rather than confounded with the two knobs that already helped.

## Sweep verdict (2026-10-18 03:51, n = 3 dev prompts, judged; SWEEP.md)
Five online configurations, all budget-matched at ~2032 NFE, versus the fixed 4-wording bank (`probe3_jev_prune`):
**none beats it on any clean held-out metric.** Deltas vs the control: root-only ir −0.017 / hpsv3 +0.081 /
pickscore +0.004 / vqascore −0.004 (parity); wide −0.009 / −0.601 / −0.220; k5 −0.042 / −0.145 / −0.051;
deep −0.049 / −0.750 / −0.173; original −0.137 / −0.773 / +0.015.
Mechanism confirmed: the original arm's deficit was the keep gate (top-2 wordings out of a 12-wording bank =
a noisier ranking); widening it to 3 recovers nearly all of it, to parity, not to an advantage.
Generating at step 8 (`deep`) is the worst and costs ~90% more wall-clock. Configurations swap ranks prompt by prompt
(k5 wins 2 of 3 outright yet has a lower mean), so n = 3 cannot order them; the spread among the top three is 0.017.

**The cost finding is the useful one.** `sw_root` — 4 extra wordings written at the root with NO image, NO readouts —
matches the control on every metric with **2 VLM calls per prompt against the control's 122** (901 s vs 866 s).
The control's per-node preview readouts (~100 s of VLM time per prompt) therefore buy nothing either. Taken with the
online result: on this task the search plus a reasonable wording bank does the work, and both the per-node perception
and the mid-trajectory generation are overhead. That is a negative result worth reporting in the ablation, not dropping.

### State A/B result + a bug the A/B exposed (2026-10-18 07:46)
`sw_beststate` (same config + `--use_state`) minus `sw_best`, ir per prompt: +0.007, +0.060, −0.055 → mean +0.004.
**Per-prompt value memory works** (records carry 18-24 wordings with visit counts and mean outcomes) but gives no net
gain on the search objective at n = 3; it helped most on the prompt with the largest bank (birds, +0.060, the best any
online config reached there) and hurt on another. **The cross-prompt base never populated: 0 rows, 0 attributed edits.**
Cause: edit attribution needs a parent and child that BOTH have checklist readouts, but readouts only happened where
generation happened (`depth <= online_depth = 1`), and every depth-1 node's parent is the root, which has no image and
therefore no statuses — so `edit_outcome()` could never fire. Fixed by separating `--readout_depth` from
`--online_depth` (default unchanged, so queued runs are unaffected); set readout_depth = online_depth + 1 to enable it.
**The cross-prompt wording base is therefore still untested.** Testing it properly needs a training split large enough
to accumulate rows, then a frozen base evaluated on held-out prompts.

### The experiment that actually answers the question
Not "which arm wins at one budget" but "which arm has the better frontier": sweep n_sims ∈ {10, 20, 40, 80} for blind
MCTS and one Jev arm on the same prompts, judge all, and plot hpsv3 against ir. If Jev's curve is above blind's, the
decision model buys a better trade-off; if the points fall on one curve, Jev only moves along it and the mechanism
story collapses. Everything measured so far is consistent with the latter.

## Budget frontier, blind MCTS (2026-10-18 11:36, n = 3 dev prompts) — reframes the whole study
| sims | NFE | ir | hpsv3 | pickscore | vqascore |
|---|---|---|---|---|---|
| 0 (no search) | 56 | 1.142 | 10.271 | 22.299 | 0.547 |
| **10** | **616** | **1.488** | **10.744** | 22.385 | 0.615 |
| 20 | 1176 | 1.494 | 9.748 | 22.233 | 0.617 |
| 40 | 2200 | 1.541 | 9.594 | 22.386 | 0.605 |
| 80 | 4120 | 1.541 | 9.594 | 22.386 | 0.605 |

**1. The search saturates at or before 40 sims.** At 80 sims the returned images are BYTE-IDENTICAL to 40 on all three
prompts (same `image_sha256`, same action paths) after spending 4120 NFE instead of 2200. The extra 1920 NFE/prompt
bought literally nothing.
**2. There is a knee at 10 sims.** It captures 1.488 of the 1.541 ir eventually reached (97 %) while scoring hpsv3
10.744 — ABOVE the no-search baseline (10.271) and better than any other search point measured. Everything past it
buys +0.053 ir and costs −1.15 hpsv3; the damage happens between 10 and 20 sims.
**Consequence: every arm in this study ran at 40 sims, i.e. 4x past saturation AND past the hpsv3 cliff.** All the
arm-vs-arm comparisons were made at the worst point of the trade-off. The question to ask is no longer "does Jev beat
blind at 40 sims" (both saturated) but "does Jev at 10 sims beat blind at 10 sims" — if not, a smaller budget already
buys what the decision machinery was supposed to buy, for free.

**blind@10 dominates jev@10 and jev@20** (higher on BOTH axes, fewer NFE) and **essentially ties jev@40**
(ir 1.488 vs 1.502, hpsv3 10.744 vs 10.806) using **616 NFE vs 2032 and 0 VLM calls vs 122** (238 s vs 866 s per prompt).
**The decision machinery does not buy a better frontier — it reaches the same point on the same curve at ~3x the cost.**
What controls the ir/hpsv3 trade-off is the search budget; the right move is to spend less of it.
Not claimed: the Jev curve is non-monotonic (hpsv3 10.806@40 -> 9.854@44 -> 9.058@80); a 10 % budget change should not
move it a full point, so per-prompt variance (hpsv3 spans 8.8-13.1 across these 3 prompts) is comparable to the
differences. The ordering of nearby points is NOT established. What survives the noise is the headline above.

### Practical recommendation
Operate blind key-step MCTS at ~10 sims (616 NFE). It gets 97 % of the attainable ir gain with hpsv3 ABOVE the
no-search baseline, needs no VLM/Jev servers, and is 3-4x cheaper than anything else tested.
### To overturn this you would need
(a) the same frontier on 25+ prompts (3 is far too few given the hpsv3 spread), and (b) a Jev point that is strictly
above the blind curve — not merely a different point on it.

## NFE reduction: truncated rollouts (2026-10-18 16:20, 3 prompts x 8 trajectories; main/truncation)
83 % of search NFE is rollouts run to step 28 purely to get a terminal score. Can they stop early?

|---|---|---|---|---|
| step 4 | 86 % | **−0.735** | 0/3 | 0.276 |
| step 8 | 71 % | −0.234 | 0/3 | 0.191 |
| step 12 | 57 % | +0.479 | 0/3 | 0.467 |

| step 20 | 29 % | +0.901 | 1/3 | 0.061 |
| step 24 | 14 % | +0.921 | 3/3 | 0.000 |

**Truncate at step 16** (or 20 to be conservative): ~43 % of rollout steps = ~36 % of total NFE, Spearman 0.84.
Rank correlation matters more than argmax here because UCB1 averages many backups.
**Stacked with the budget finding: 2200 NFE -> 616 (10 sims) -> ~400 (truncate at 16) = 5.5x.**
**ImageReward ANTI-CORRELATES at step 4 (−0.735)** — scoring an early x0 preview with the reward model is worse than
guessing. Audit anything that evaluates early previews with IR (e.g. the noise-injection path at steps 1-2).

### The one remaining place the decision model could earn its keep
IR is useless or harmful before step ~12, yet a VLM can plainly read composition in a step-4 preview (eye-checked).
So the open question is NOT "does Jev pick better actions than UCB1" (it does not) but **"can Jev rank partial
trajectories at step 8, where IR anti-correlates?"** If yes, whole rollouts get pruned before they start — a larger
saving than truncation, and something no cheaper method here can do. Design: at step 8, show Jev the x0 previews of
the live rollouts and ask it to pick the k most promising; measure rank correlation of its ordering against the final
IR of the same trajectories (the data format of main/truncation is directly reusable).

## How Jev actually decides, and why it loses at 10 sims (2026-10-18 17:00)
Mechanism as implemented: per node, two Jev questions (rank 4 wordings; rank 7 CFG levels), each order-averaged over
3 shuffled orders; keep = top-2 wordings x top-3 CFGs + forced anchor (~7 of 28 actions); UCB1 searches only those.
Measured over the 33 decision nodes of `fr_jev_s10`:
- **Jev ranks CFG 7.0 first at 33/33 nodes** — independent of prompt, step and preview. A constant, not a decision.
- Kept actions skew high: CFG 7.0 x66, 6.0 x52, 4.5 x41 (mostly the forced anchor), vs 4.0 x8, 3.5 x12.
- Its CFG confidence is partly illusory: mean top-prob 0.705 vs mean order-spread 0.288; on 5/33 nodes the top
  probability is smaller than its own order-noise. Wording is near-constant too (keeps variant 0 x124 vs 27-42).
**Label-sensitivity probe** (`scripts/cfg_label_probe.py`, 12 real nodes re-asked under 4 labellings, faithful state):
current 12/12 CFG 7.0 (top-prob 0.747) — replicates the 33/33; **neutral bare numbers still 10/12** (0.499);
reversed valence 6/12 (0.462); symmetric 11/12 (0.873). **The preference is the model's prior, not my option text** —
labels modulate confidence but do not create the preference. (An earlier version of this probe reconstructed the state
wrongly, passing the prompt_id instead of the prompt text, and wrongly suggested the labels flipped the choice.)
**Why this costs more at 10 sims than at 40:** Jev supplies a prior and the kept set lives in a narrow high-guidance
region; high CFG is also the oversaturation mode. At 10 sims the prior IS the policy -> worse on both ir and hpsv3.
At 40 sims UCB1 accumulates enough evidence to overrule it.
**Fix:** take Jev off the CFG decision (it contributes a constant) and let UCB1 search the full 7-value bank; keep Jev
for the wording choice, which at least varies with content. If its CFG opinion is wanted, use the probabilities as a
soft PUCT prior that evidence can override, not a hard filter that deletes 4 of 7 options before the search starts.

## Joint (wording, CFG) selection (2026-10-18 17:30) — the diagnosis was right, the fix changes nothing
The factorised design (rank wordings, rank CFGs, keep top-nv x top-nc) assumes separability. Measured on 8 real nodes
(`scripts/joint_vs_factored.py`): **the best CFG differs across wordings at 8/8 nodes**; separability (rank-1 explained
variance) 0.937; **the factorised kept set misses ~46 % of the joint top-6**; no order-echo degeneracy (r 0.11-0.64),
so Jev-Omni handles 28 joint options fine (it was the VLM's JSON ranking that degenerated, not this classifier).
**And the degenerate CFG prior is an artifact of the marginal question**: asked in isolation Jev answers 7.0 at 33/33
nodes, asked jointly its choices spread over 3.5-7.0.
Joint mode implemented (`vlm_mcts.py --joint`, factorised path retained) and run at the 10-sim knee:
| arm @10 sims | ir | hpsv3 | pickscore | vqascore |
|---|---|---|---|---|
| blind MCTS | 1.488 | 10.744 | 22.385 | 0.615 |
| Jev joint | 1.384 | 10.128 | 22.331 | 0.605 |
| Jev factorised | 1.370 | 10.165 | 22.364 | 0.641 |
joint − factorised: ir +0.014, hpsv3 −0.037, pickscore −0.033, vqascore −0.036 — **no improvement in any direction**.
(The factorised rerun reproduced the earlier run's per-prompt scores exactly, so the pipeline is deterministic and this
is a clean one-variable comparison.)
**Conclusion: the low-budget deficit is not about HOW the action set is chosen, it is about restricting it at all.**
At 10 sims blind tries 10 distinct root actions of 28; the Jev arm tries 7 then goes deeper. Breadth beats guided depth
at small budgets, and better guidance cannot recover the coverage pruning discards.
**Design implication: stop deleting options.** Use Jev as a soft PUCT-style prior that evidence can overcome, or apply
it where nothing cheaper works (the early steps where IR anti-correlates). Hard pruning is the wrong interface for a
decision model whose rankings carry this much order-noise.

## PUCT soft prior (2026-10-18 20:12) — softening the interface makes it WORSE
`vlm_mcts.py --joint --puct`: keep ALL 28 actions, select by Q + c_puct*P*sqrt(N)/(1+n) with P = Jev's joint
probability over the bank, rollouts sampled from P instead of uniformly. Judged at 10 sims on the dev prompts:
| arm @10 sims | ir | hpsv3 | pickscore | vqascore | Jev's influence |
|---|---|---|---|---|---|
| no search | 1.142 | 10.271 | 22.299 | 0.547 | none |
| **blind MCTS** | **1.488** | **10.744** | **22.385** | 0.615 | none |
| Jev joint (hard prune) | 1.384 | 10.128 | 22.331 | 0.605 | action set |
| Jev factorised (hard prune) | 1.370 | 10.165 | 22.364 | **0.641** | action set |
| Jev PUCT (soft prior) | 1.219 | 10.661 | 22.314 | 0.576 | action set + selection + rollouts |
**The ordering on ir is monotone in how much influence Jev's opinion has.** PUCT gives it the most channels and lands
barely above no-search. Failure shapes seen in the trees: on q0011 it drove to depth 4 (vs depth 2 for the pruned arms)
— a peaked prior with no untried-first rule concentrates instead of covering; on q0027/q0041 it spread at depth 1 but
the prior-sampled rollouts were correlated, which a best-of-rollouts return punishes.
**Conclusion: the interface was never the problem — the prior is.** A soft prior is the textbook fix for a hard filter
and it made things worse, because what is being softened is high-CFG-biased, order-noisy and largely unconditioned on
the image. Giving a bad prior more channels produces a worse search. (Nuance: PUCT does hold hpsv3 at 10.661, above both
pruned arms — concentrating the search preserves perceptual quality, it just fails to find good images.)
Untested remedies if this line is resumed: temper the prior (p^(1/T)) or add root Dirichlet noise, both standard
anti-concentration fixes; neither addresses the prior's content.

## WHY Jev does not help: it is a question-type mismatch, not a state or plumbing failure (2026-10-18 21:00)
**The state the arms actually gave Jev** (verbatim from `logs/jev_calls.jsonl`):
```
ORIGINAL PROMPT (the only target): "<prompt>"
Denoising step 4 of 28.
VLM readout of the current preview: <2 sentences, almost always "matches the prompt but is blurry">
The sampler will apply the chosen setting for the next denoising steps; the FINAL image must match the ORIGINAL prompt.
```
It never contains the CFG that produced the preview, the action path, any alternative to compare against, or any
outcome feedback. State strings are 0.67 similar across the nodes of one prompt — mostly rephrasings of one observation.
**State ablation** (`scripts/state_ablation.py`, 8 real nodes, CFG question): top choice changed under
image withheld 0/8 (TV 0.069), readout swapped for another node's 1/8 (0.190), readout deleted 0/8 (0.177),
**current CFG added to the state 1/8 (0.238)**. It answers 7.0 when the preview was made at 4.5 and 7.0 when the
preview was already made at 7.0. Enriching the state does NOT fix it — which kills the "missing error signal" theory.
**Image sanity** (`scripts/jev_image_sanity.py`): "sharp or blurry?" 7/7 correct (P=0.999 on step-4 previews, 0.74-0.86
on finished images); "which description matches?" 3/3 correct (P≈1.000). **The image path is live and Jev reads these
previews with near-certainty.**
**Diagnosis: Jev answers PERCEPTION questions from evidence and POLICY questions from a lexical prior.**
"Is this blurry?" / "does this match the description?" are matching tasks — what a typed-decision classifier is trained
for — and it nails them. "Which CFG should the sampler use next?" requires predicting how a control parameter will
change a future trajectory; nothing in the image answers it, so it falls back on the option wording (constant 7.0,
unmoved by image/readout/current-CFG, but shifted by relabelling to 6/12 under reversed valence).
**Design rule that follows: never ask Jev what setting to use; ask it which outcome is better.**
Replace "which CFG for the next steps?" with: run the candidate children a few steps, decode their previews, ask
"which of these previews better matches the ORIGINAL prompt?" — a matching question, in distribution.
This also explains the one thing that helped: per-prompt memory (+0.30 hpsv3) converted part of the decision into
evidence ("wording X scored 1.42, Y scored 1.19") instead of asking for a control prediction.
It is the same shape as the remaining opportunity: at step 8, where IR anti-correlates (−0.735 at step 4), ranking
SIBLING previews by prompt match is a perception question Jev can ground — and it prunes whole rollouts.

## Retrieval-grounded Jev (2026-10-18 21:49) — the first interface that does NOT damage the search
User's design: don't ask Jev what setting to use; show it the FINAL images that nearby configs already produced in this
search, each captioned with its (wording, CFG), its end-of-trace VLM assessment and its reward, and ask which panel's
final image best matches the ORIGINAL prompt. `scripts/jev_retrieval.py`, `run_retrieval.sh`.
Implementation notes: every finished rollout is kept as a trace (actions, final image, reward, VLM assessment - one

returned the same wording at adjacent CFGs, i.e. near-identical images - a degenerate comparison, see sheets); the
current preview plus up to 3 retrieved finals are tiled into ONE labelled strip; the winning panel's config plus its
CFG neighbours and the anchor become the node's action set. First 2 sims explore the full bank to build evidence.

|---|---|---|---|---|---|
| q0011 | 1.692 | 1.698 | 1.698 | 1.679 | 1.554 |

| mean | 1.487 | 1.489 | 1.384 | 1.370 | 1.220 |
q0027 is the prompt every other Jev arm collapsed on (0.83-0.86 vs blind 1.074); retrieval matches blind exactly.
8 of 11 nodes per prompt were decided by retrieval, so the mechanism drove the search rather than falling back.
Judged: retrieval − blind = ir −0.001, pickscore +0.026, vqascore +0.023, **hpsv3 −0.424**; 271 s/prompt vs 238 s,

**Verdict: the damage is gone, the gain is not there.** Every earlier interface cost 0.10-0.27 ir against blind; this

**Where it could still win:** apply the same retrieval-grounded comparison in the EARLY window (before step 12) where

## Multi-reward: Jev picks WHICH REWARD each node follows (2026-10-19 02:20)
The one measured gap left in this study is that search climbs ImageReward while destroying HPSv3 (the 2026-10-18 09:30
correction). A reward-preference decision attacks that directly. Two checks came before any building.

### Check 1 — is there anything to choose between? (zero GPU, over the existing `scores.csv`)

| q0027 | 34 | −0.349 | −0.022 | +0.340 |
| q0041 | 34 | +0.731 | +0.651 | −0.186 |
| q0047 | 5 | +1.000 | +0.900 | +0.100 |
| q0055 | 5 | −0.800 | −0.800 | +0.700 |
| **mean** | | **+0.014** | **+0.151** | **+0.216** |

ImageReward and HPSv3 rank the same images **essentially independently** (+0.014), swinging from −0.80 to +1.00 by

### Design — why this needs NO normalization (the user's correction)
The obvious construction min-max normalizes each reward onto a shared scale and averages (`composite_*` backends,
`_COMPOSITE_*_RANGE`). That is arbitrary, and the moment a node changes objective it makes UCB1 backups
non-stationary. `scripts/jev_reward_select.py` never compares two rewards numerically:
* each reward gets a **FOCUSED AREA** — the class of deficiency it can actually see (`REWARD_FOCUS`):
  imagereward = CONTENT/FAITHFULNESS (what is in the picture), hpsv3 = APPEARANCE/CRAFT (how it looks),
  pickscore = KIND/FRAMING (which picture was made);
* every finished rollout is scored under **all three** backends and its score VECTOR is accumulated at every node on
  its path — three independent running sums per action, not one;
* a node selects one reward and reads **only that column** for UCB1 and exploitation, so its statistics are always in
  one reward's native units. Re-deciding a node's reward costs nothing and corrupts nothing: the other two columns
  were being kept anyway. The returned image is chosen under the reward the ROOT settled on — one criterion per
  prompt, never a mixture.
* VQAScore is deliberately **not** a search reward: it stays a fully held-out judge, which no earlier multi-reward
  arm in this study had.
Jev's input is the end-of-trace VLM reports — free text saying what is wrong — matched against the focus statements.
That is a MATCHING question over evidence, the only kind the 2026-10-18 21:00 ablation showed Jev answers from
evidence rather than from a lexical prior.

| reports describe missing/duplicated/broken CONTENT | imagereward 9 | **9/9** |
| reports describe oversaturation / plastic / flat light | hpsv3 9 | **9/9** |

**45/45, and the choice changes across conditions for 9/9 prompts.** Contrast the CFG-policy probe, where withholding

The +1.836 hpsv3 / −0.077 ir figure computed from `scores.csv` was a **max over 34 heterogeneous arms** — an extreme
order statistic, as flagged but under-weighted. Under the controlled comparison (two arms differing ONLY in the reward),
the per-prompt oracle headroom over the best fixed arm is:
| metric | oracle | best fixed | headroom |
|---|---|---|---|
| ir | 1.3548 | 1.3438 | **+0.0110** |
| hpsv3 | 11.7132 | 11.6994 | **+0.0138** |

| qwen_alignment* | 0.8328 | 0.7998 | +0.0329 |

(+0.014) is still correct and is still the reason reward CHOICE matters — but choosing it per prompt, rather than once
per run, is worth ~0.01.
And Jev's root choice is responsive without being predictive: it matched the fixed arm that actually scored higher on
that prompt in 6/9 prompts judged on ir but **4/9 judged on hpsv3** (chance is 4.5/9).

### Verdict: the useful result is `rs_hps`, and it needs no decision model at all
`rs_hps` moves cleanly along the frontier — **hpsv3 +0.879 (CI excludes 0) for ir −0.182, with every held-out metric
unchanged** (hpsv2 +0.001, qwen_alignment −0.002 [−0.088, +0.110], vqascore −0.021 [−0.068, +0.015]). That is one flag
(`--reward_policy hpsv3`), zero VLM calls, zero Jev calls. `rs_jev` costs ~16 Jev + 10 VLM calls per prompt to land
between the two fixed arms, is DOMINATED by `rs_hps` on both held-out frontiers ((vqascore, hpsv3) and
(qwen_alignment, hpsv3)), and is significantly worse than blind on VQAScore.
**Recommendation: pick the reward you want per RUN. Do not build a per-node reward selector.**
(Third time this study has reached the same shape of answer: the decision is real and Jev can make it, but the decision
is not worth enough to pay for. The measured operating point stands — blind key-step MCTS, ~10 sims, rollouts truncated
at step 16, and `--reward_policy hpsv3` if HPSv3 is what you care about.)

## THE AXIS THE WHOLE STUDY HELD FIXED: the initial latent (2026-10-19 04:00)
Every script here built its start latent with `make_latents(ctx, seed=42, ...)` — **one noise sample, identical across
every arm and every prompt**; `config.json` even records `noise_actions: off (steps > 4)`. Two days of search explored
(wording x CFG) at fixed z0. At 28 Euler steps a complete generation is **56 NFE**, so the 616-NFE operating point
every arm was matched to buys exactly **11 full generations** — making "best of 11 initial noises at the anchor" an
exactly budget-matched, search-free competitor that had never been run.

## Planned arm: adaptive noise budget — abandon on saturation + expand the pool every 5 sims (specified 2026-10-19 04:30)
Best-of-k noise allocates budget UNIFORMLY. The user's design allocates it adaptively, with two decisions that are the
same decision in opposite directions:
* **abandon** (contract): while sampling an initial noise, at checkpoints ask whether it has saturated — if so stop
  spending on it and draw the next noise;
* **expand** (grow): every 5 simulations of action search, ask whether to spend the next budget on a NEW initial noise
  instead of more (wording x CFG) search on the noises already in hand.
Shared cost model, exact for this sampler: **2 NFE per Euler step**; a noise taken to step t costs 2t, finishing it
costs 2(28−t), a complete generation is 56, and the matched budget is 616 NFE. The allocation question is sharp
because the two axes are now measured: action search is worth ~**+0.88** hpsv3 (`rs_hps` vs blind) and the initial
noise carries a mean per-prompt range of ~**4.52** hpsv3, so a correct allocator should push budget toward noise.

**Order of work (the discipline that has paid three times here): ceiling first, then the arm.**
`scripts/noise_ladder_probe.py` (running) records, for 9 prompts x 32 initial latents at the anchor action, the x0
preview score at steps 4,8,12,16,20,24 plus the finished score — one full generation per noise, so every policy is
then simulable offline at any budget. `scripts/ladder_sim.py` then reports at 616 NFE:
| quantity | what it bounds |
|---|---|
| across-noise Spearman(partial score at step t, final score) | whether a noise is judgeable at all at step t |
| `uniform best-of-11` | the incumbent (`ns_bo11_hps`) |
| `oracle(t,n,m)` — screen n to step t, rank by TRUE final, finish m | **the ceiling no abandonment rule can beat, Jev's included** |
| `partial(t,n,m)` — same, ranked by the partial reward score | what a FREE non-model screen already captures |
| `random(t,n,m)` — same, ranked at random | how much is merely seeing more noises, not information |
A Jev saturation/expansion decider is worth building only if `oracle − uniform` is large AND `partial − random` is
small — i.e. the decision matters and the cheap reward screen cannot already make it. Note the best-of-k curve was
already flattening at k=16 (+0.008 over k=11), which is the main reason to expect a small ceiling: screening buys a
larger effective k, and a larger k is worth little once the curve is flat. Extending the curve to k=32 is part of the
probe for exactly this reason.
Controls planned for the arm itself, all at 616 NFE: `nx_jev` (both decisions), `nx_never` (pure action MCTS =
`rs_blind`), `nx_always5` (expand every 5 sims unconditionally), `nx_random` (expand/abandon at Jev's empirical rate
but at random), and `ns_bo11_hps` (uniform, the incumbent). Selection on HPSv3 throughout — `ns_bo11_ir` showed that
selecting noise on ImageReward significantly loses the held-out alignment judge.

|---|---|

### JUDGED (2026-10-19 16:45, n = 9): the bugs were real but immaterial, and my proposer is a net LOSS
| arm | ir | hpsv3 | pickscore | hpsv2* | qwen_align* | vqascore* |
|---|---|---|---|---|---|---|
| `pb_orig` (shipped bank, pre-fix loader) | 1.1128 | 10.8414 | **22.9702** | 0.2953 | 0.6905 | **0.8124** |
| `pb_fixed` (shipped bank, artifacts stripped) | 1.1015 | **10.8563** | 22.9559 | 0.2948 | 0.6937 | 0.8116 |

not a quality win — worth keeping, but it does not revise any earlier result in this study.

**2. MY PREDICTION WAS WRONG.** I predicted the faithful bank would lose hpsv3 but win the faithfulness judges,
because my proposer forbade style words while HPSv3 pays for them. It won neither:
`pb_clean − pb_orig` vqascore **−0.0089 [−0.0315, +0.0041]**, qwen **+0.0058 [−0.0302, +0.0366]** — no difference on

**3. The surviving explanation is DIVERSITY, and it is the generalisable lesson.** The clean bank keeps 2.67 distinct

prompts with 3-4 lost **−0.132**; corr(distinct wordings kept, hpsv3 delta) = **+0.377**.
Why the corruption was harmless in the first place: **reward-guided search SELECTS, so a corrupt variant only wins
if it actually scores well.** In `pb_orig` 121/162 generations (75%) used a non-base wording and 7/9 returned images
did — the bad ones were available and simply lost. Selection filters bad proposals; it cannot invent proposals that
are absent. **In reward-guided search, proposal DIVERSITY is worth more than proposal CORRECTNESS.**

### Verdict on the proposer
**Do not adopt `pb_clean` as it stands** — it costs 0.21 hpsv3 and buys nothing. Keep the shipped bank, now
artifact-free. If the bank is revisited, the target is the validator's **56% yield**, not its content rules: produce
4 distinct wordings that each pass the numeral/negation/content-retention check, rather than 2.67 that do.
Dropping the "no style words" prohibition is still worth trying on that basis (it should raise yield), but the
judged data gives no reason to expect a faithfulness gain from it.
